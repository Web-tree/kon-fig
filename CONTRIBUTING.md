# Contributing to Kon-Fig

Open an issue or pull request against the draft. Explain the problem, proposed behavior, alternatives, security implications and compatibility impact.

Normative changes belong in docs/specification; update related schemas and fixtures in the same PR. Guides are informative and must not introduce conflicting requirements. Use BCP 14 language only for normative requirements.

Use Markdown with YAML front matter (title, description), relative links and fenced code blocks. Keep one topic per page, stable filenames and navigation entries. Do not put secrets into examples or fixtures.

See [governance](docs/project/governance.md) for the proposed decision and licensing process. Licensing awaits maintainer approval.
