# Governance

Kon-Fig is an early Web-tree project. The following governance and licensing terms are proposed for maintainer approval, not asserted as already adopted.

## Decision process

Discuss normative changes in public GitHub issues or pull requests. Each proposal describes motivation, alternatives, interoperability/security implications, migration impact, updated schemas and tests. Maintainers approve changes by review. Breaking changes require explicit versioning and a migration discussion. Publish tagged snapshots of the specification and corresponding conformance fixtures.

## Licensing

Proposed: CC BY 4.0 for specification prose, Apache-2.0 for machine-readable schemas, examples, fixtures and future implementation. This offers a clear documentation reuse grant and an explicit patent grant for code. Maintainers may instead select MIT consistently with the upstream ACS implementation. The repository must include full applicable license texts and clear per-directory notices before representing the project as openly licensed. This draft does not itself grant those licenses. Any upstream copied material must retain required notices.

## Security and contributions

Establish a private vulnerability reporting channel before stable release. Contributors should never submit real credentials, private configuration or third-party data without authorization. No contributor agreement or patent policy beyond the chosen licenses is implied by this draft.
